# ADR-002: Границы native admin URL, прав и ввода

## Контекст

Расширение работает внутри native admin OpenCart, где URL, разрешения и POST-ввод проходят через собственные механизмы платформы. Ошибка на этих границах может ломать формы или обходить ожидаемый отказ.

## Решение

URL helper возвращает raw URL; HTML-представление экранирует его ровно один раз. Доступ проверяется штатными `access`/`modify` правами пользователя OpenCart на каждом маршруте; закрытые native data routes дают отказ независимо от меню. В custom admin обработчиках строки `Request::clean` декодируются ровно один раз перед серверной валидацией и санитизацией, затем экранируются при HTML-выводе. Публичный MVC raw `$_POST` этим правилом не меняется.

## Почему

Отвергнуто двойное экранирование URL: оно портит `&` в `user_token` и action. Отвергнуты собственные обходные токены и проверки только по видимости меню: они расходятся с native ACL. Отвергнуто повторное декодирование публичного ввода: это меняет его семантику и границу доверия.

## Последствия

Ссылки и формы сохраняют query-параметры; прямой запрос к запрещённому маршруту также отклоняется. Rich HTML и буквальные амперсанды/кавычки проходят ожидаемую обработку без ослабления allowlist-санитайзера.
