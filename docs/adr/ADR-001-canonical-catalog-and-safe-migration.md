# ADR-001: Канонический каталог и безопасная миграция

## Контекст

У CatPart уже есть рабочие таблицы каталога, идентификаторы, связи и публичные потребители. Требуется управлять ими через OpenCart 4.1.0.4, сохранив текущую витрину и возможность отдельно проверять перенос.

## Решение

Оставить таблицы CatPart единственным каталогом; редактировать их через расширение OpenCart. Заказы хранить в штатных `oc_order`, `oc_order_product`, `oc_order_history`, дополняя снимками и метаданными `cp_*`. Перенос выполнять whitelist-миграцией в изолированную БД: preview, явное применение, сверка и повторный additive/upsert без удаления неизвестных данных. После появления новых заказов откат кода не должен восстанавливать старую БД поверх них.

## Почему

Отвергнут второй каталог OpenCart с синхронизацией: он дублирует сущности и рискует разойтись с текущими ID, связями, поиском и корзиной. Отвергнуто копирование всей исходной БД: оно переносило бы посторонние данные и делало откат опасным.

## Последствия

Публичные модели CatPart остаются потребителями канонических записей; ядро OpenCart не правится. Миграция должна быть ограничена разрешёнными таблицами, идемпотентна и проверяема на клоне. При откате сохраняются данные, созданные после переключения.
