# ADR-003: UTC для публикации статей

## Контекст

Существующие `blog_posts.published_at` содержат naive даты, созданные при системной зоне Europe/Moscow; новая логика сравнивает даты публикации в UTC.

## Решение

Считать исходные naive значения временем Europe/Moscow, сохранить оригиналы и преобразовать их в UTC ровно один раз на изолированной копии. Новые SQL даты хранить в UTC, PDO-сессию устанавливать в `+00:00`; пользовательский ввод/отображение публикации переводить через Europe/Moscow. `TIMESTAMP` с уже действующей семантикой СУБД вручную не сдвигать.

## Почему

Отвергнуто трактовать старые naive значения как UTC: это сдвинет фактическое время публикации. Отвергнут повторный ручной сдвиг `TIMESTAMP`: зона уже применяется СУБД и возникнет двойное преобразование.

## Последствия

Маркер миграции и сохранённый оригинал позволяют доказать однократность преобразования и безопасный повтор запуска. Видимость черновиков, отложенных и опубликованных записей сравнивается в одной временной шкале.
