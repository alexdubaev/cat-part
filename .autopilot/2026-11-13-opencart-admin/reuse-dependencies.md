## Native schema OpenCart4.1.0.4

Фактический источник схемы ZIP: **`upload/system/helper/db_schema.php`**. `upload/install/opencart-en-gb.sql` содержит seed INSERT, не CREATE TABLE. Установщик `upload/install/model/install/install.php` генерирует CREATE из helper.

В этих четырёх definitions нет `not_null` у обычных полей. Генератор добавляет NOT NULL только при явно true `not_null`; PK/auto_increment не допускают NULL. Foreign-описания есть в metadata, но блок добавления FOREIGN KEY в installer **закомментирован**. Нельзя считать их действующими FK constraints. Actual installed schema надо проверить SHOW CREATE на изолированном стенде. Все четыре engineInnoDB/charsetutf8mb4/collateutf8mb4_unicode_ci, installer ROW_FORMAT=DYNAMIC.

## Native model — поведение, которое нужно учесть

- ZIP `upload/catalog/model/checkout/order.php`: addOrder/addProduct/addHistory и связанные методы; `upload/admin/model/sale/order.php` читает native orders/products/history и рассчитывает native sales. Запись через модель не добавляет request-key/idempotency/manager/audit сама по себе.
- **`addHistory` не является чистой записью истории**: вход в config_processing_status/config_complete_status запускает subtract stock, coupon/reward подтверждение; выход может restock; complete может affiliate/subscription. Для заказов-запросов нужна явная защита от этих побочных действий. Dedicated request status IDs не включать в processing/complete и проверить direct/native update пути. Альтернатива — CatPart transactional service пишет те же native order/history rows безопасно, без вызова commerce lifecycle; обосновать это в interfaces.
- Native addOrder использует `$data[...]` для большого набора полей, включая адресные/payment/shipping data, а SQL пишет NOW(); не передавать неполный frontend payload напрямую. AddProduct пишет model64/name255 и числовые price/total/tax через float — точные nullable исходные условия должны иметь собственный immutable snapshot рядом с native row.
- Native mysqli connection синхронизирует time_zone с PHP `date('P')`. Отдельный PDO adapter не наследует эту сессию; установить согласованную UTC time_zone и единое преобразование для admin/storefront/sitemap.
- Native report getTotalSales может учитывать статусы платформы. CatPart отчёты запросов должны выбирать собственную семантику, не показывать неподтверждённые суммы как выручку.

## Практический состав минимального пакета

Собственное `extension/catpart` + маленькие адаптированные input validators, собственные controllers/Twig с native CKEditor/filemanager, linked metadata/outbox/idempotency/audit tables. PHP baseline8.1+: **pdo_mysql, mbstring, dom/libxml, zip, fileinfo**; curl/OpenSSL только при SMTP transport, iconv при1251 CSV. Native filemanager resize имеет дополнительные штатные требования OpenCart, которые проверяет installer. Не импортировать CMTEH storefront, EditorialDefaults, InventorySchema, InventoryNativeGuard, warehouse UI или install/upgrade целиком.

Это dependency audit, не утверждение работоспособности переноса. Новые PHP/DB/browser проверки NOT RUN.
