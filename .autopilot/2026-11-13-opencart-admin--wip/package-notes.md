# Ограничения итогового пакета и постоянного стенда

- Установочный пакет проверять после доменных тасков из чистого clone/export; никакой публикации на боевой хостинг. README должен различать источник пакета, реально выполненные локальные проверки и NOT RUN на хостинге.
- Владелец требует после успешного merge удалить собственную временную ветку/worktree. Поэтому рабочий стенд должен пережить удаление D:/codex/cat-part/admin-unified: установить проверенный ZIP в постоянный D:/codex/cat-part/admin-stand (это изолированная папка, не чужой worktree). tools/admin-dev.py имеет --runtime. Исходники/extension/router/staticassets должны читаться из постоянной установки, а не удаляемого worktree.
- Существующий source images path D:/codex/cat-part/cat-part/local-dev/site/upload разрешён только для чтения/раздачи через router; собственные newmedia/uploads/config/captures находятся в стенде. Не менять source uploads/config/DB/users или использовать hardlink для изменяемых файлов.
- Проверка нового источника: свой stand DB catpart_admin_*; source local_catpart — только catalog whitelist. Synthetic staff/accounts новые и private. При update не заменять действующие edited records/новые orders/leads/settings. Нельзя повторно применять defaultseed поверх пользовательских изменений.
- Архив строить по allowlist отслеживаемых исходников и pinned upstream ZIP с проверкой SHA; не rglob всего рабочего каталога. Исключить config.php/config.local.php/private/runtime/captures/accounts/SQL/useruploads/git/.autopilot server*. Факты публичного CatPart контента допустимы; CMTEH данные/настройки нет.
- Deterministic archive + SHA256, upstream lock, source revision/filemanifest/provenance/licenses, actual installedextensions+compatibility dependency matrix, admin guide, rollback instructions. Не обещать поддержку хостинга по Windows lint.
- Backup/restore только на своей DB и своей новой restore schema. Code rollback после новых обращений не восстанавливает старую DB поверх новых записей. Проверить повтор миграции/обновления, старую корзину identityIDs, unknown sentinel, новые order/lead не потерялись.
- Реальный browser smoke на установленном пакете: native admin roles/directACL, editphone→public, product→search/cart, article draft/publish, nativeorder/lead persistence/idempotency/mailfault/map-clear. Не запускать большую viewport matrix.
- Сценарии подробно в acceptance-scenarios.md. Последний checkset должен соответствовать публикуемому source; docs-only landing metadata не требует повторять неизменившиеся продуктовые тесты.
