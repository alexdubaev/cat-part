# Спецификация: единая админка CatPart

## 1. Задача и границы
Владелец редактирует реальные данные витрины через одну настоящую установку OpenCart 4.1.0.4, посетитель видит результат, менеджер обрабатывает сохранённые заказы и обращения. Существующие оформление, маршруты и функции сохраняются. Язык интерфейса русский. Код расширения CatPart, ядро upstream не правится. Наследованных исходников CatPart-админки нет: это подтвердил владелец 2026-11-13. Никаких действий на действующих CatPart/CMTEH. Только собственная локальная БД, тестовые сотрудники и синтетические обращения. Совместимые библиотеки/редактор СМ ТЕХНО адаптируются выборочно; целый модуль не устанавливается, так как включает другую витрину и складские правила.

## 2. Один источник и инвентаризация
Архитектурное решение: исходные таблицы каталога CatPart остаются единственным каталогом, редакторы extension/catpart работают прямо с ними. Это сохраняет ID, поиск FULLTEXT, связи, старые корзины, адреса и текущие модели без рискованного двойного хранилища. Пустые стандартные таблицы товаров OpenCart не наполняются и не являются источником; штатные неподключённые редакторы и checkout недоступны на сервере. Отдельной синхронизации двух каталогов нет. Это штатная модель расширения OpenCart с собственными таблицами, не самодельная отдельная админская авторизация. Заказы — стандартные oc_order/oc_order_product/oc_order_history с дополнительными cp_* снимками и ответственным. Пользователи/роли — native oc_user/oc_user_group. Все сущности в одной тестовой БД.

| Сущность | Источник | Редактор | Потребители |
|---|---|---|---|
| Товары | products + product_images/cross/attr_values/compat и cp_product metadata | Каталог CatPart | карточка, поиск, каталог, подборки, корзина, sitemap |
| Категории | categories, исходная path и cp_category metadata | Категории CatPart | дерево, страницы, родительские выборки, меню, sitemap |
| Бренды/характеристики | brands/attributes + cp metadata | Каталог CatPart | карточка, связи, поиск, импорт |
| Статьи | blog_posts + cp_article_revision/link | Содержимое → Статьи | главная, статьи, связанные блоки, SEO, sitemap |
| Страницы/главная/меню/формы | cp_content/cp_settings | обычные формы содержимого/блоков | существующие шаблоны CatPart |
| Контакты/карта/бренд/аналитика | cp_settings | Настройки сайта напрямую | все публичные представления и структурированные данные |
| Заказы | oc_order/product/history + cp_order meta | Заказы CatPart | подтверждение, история, менеджерские экраны/отчёты |
| Обращения | cp_lead/history | Обратная связь | все формы, менеджерские экраны |
| Уведомления | cp_outbox | Обслуживание + карточки | локальный worker/capture, ошибки/повтор |
| Доступ/аудит | native oc_user/group + cp_audit | пользователи и права | каждый admin route, preview/download, журнал |

Исходный набор read-only: 7134 товара, 1161 категория/18 корней, 1 бренд, 5 статей, 23459 изображений, 122194 групп совместимости, 17966 значений характеристик. Сохранять оригиналы, строки артикулов, ID и URL. Переносить только whitelist каталога/содержимого; не переносить users/orders/клиентов/секреты другого проекта. Migration preview → явный apply на task DB → сверка counts, orphan refs, путей, хешей. Повтор additive/upsert без дубликатов, без удаления неизвестных записей. ID map identity для исходного каталога. Работа на БД-клоне оставляет исходный локальный сайт неизменным. Backup/restore проверяется в дополнительной одноразовой БД; после новых обращений откат только кода, без восстановления старой БД поверх новых данных.

## 3. Состав и удобство админки
Главная показывает реальные количества заказов/обращений/ошибок, без выдуманной выручки. Каталог, Заказы, Обратная связь, Содержимое (статьи/страницы/главная), Меню и подвал, Настройки сайта, Пользователи и права, Отчёты, Обслуживание. Нет демотоваров/категорий/клиентов/заказов и служебного списка site/mock-site. Формы с русскими подписями, нормальными полями/визуальным редактором/изображениями, без JSON/SQL/PHP. Результат сохранения и ошибки у полей, ввод не теряется; длинные названия, постраничные списки/поиск. Обычная плотность без пустот, фиксированные панели не перекрывают управление; опасные действия подтверждаются именем записи. Штатные неинтегрированные функции блокируются сервером и перечисляются в инструкции как будущие возможности, скрытие меню само по себе не ACL.

## 4. Каталог
Редактор товара: имя/строковый артикул/OEM-кроссы, бренд, основная и дополнительные категории, краткое/полное описание, характеристики, галерея/alt/подписи, цена/currency/режим по запросу, boolean наличие и условия, связанные товары/аналоги, slug/SEO/title/H1/canonical/noindex/OG, публикация/архив. Категории: parent/иерархия/описание/картинка/порядок/публикация/SEO. Изменение parent пересчитывает path потомков в транзакции без потери товарных связей, запрещает циклы. Родитель показывает потомков; дополнительные связи учитываются публичной выборкой. Бренды: имя/логотип/описание/SEO. Характеристики редактируются с единицами и значениями. Не превращать in_stock в выдуманный количественный остаток. Единая sku_norm из CatPart для поиска/админки/импорта; исходный SKU не меняется. Удалять связанное нельзя молча: понятное предупреждение/архивирование. Все разрешённые редакторы меняют единственную запись; неработающие native editors запрещены.

## 5. CSV/XLSX и массовые изменения
Пошаговая форма: файл CSV/XLSX → сопоставление колонок → предварительный разбор → создаваемые/изменяемые/неоднозначные строки/точная строка и ошибка → явное применение → итог. Проверять подпись/тип/содержимое/размер/ZIP XML безопасность; исходники вне public. Пропущенные поля/товары не удаляются и не обнуляются. Идентификация: явный ID или точный исходный SKU с нормализованным сопоставлением; неоднозначность останавливает строку. Сохранять leading zero. Повтор тех же данных идемпотентен. Лимиты показываются до загрузки, связаны с PHP/hosting и памятью/потоком, не 100 позиций и не silent truncation. Лимит файла и строк обосновать в инструкции; тест больше 100 строк. Импорт создаёт аудит и отчёт.

## 6. Статьи
Визуальный редактор (адаптировать безопасный CMTEH): абзацы/H2–H4, списки/ссылки/цитаты/таблицы/встроенные изображения с alt/подписью. Отдельный H1, анонс/обложка/OG/автор/дата, статусы черновик/публикация/отложенная/архив, связанные статьи/товары, slug/title/description/canonical/индексация. Серверная HTML allowlist, Word paste cleanup, scripts/events/style/опасные URL не сохраняются. История сохранений, restore предыдущей версии как новая ревизия с аудитом. Авторизованный preview с реальным шаблоном/без публичного токена. Draft/future/archive не доступны анонимно и не в sitemap; один predicate для всех читателей. Единая временная семантика Europe/Moscow input → UTC storage/session DB UTC и UTC PHP comparison; исходные даты переводятся явно и один раз. Существующие blog_posts/URL/изображения не теряются.

## 7. Корзина
Сохраняется текущая сессия и product ID. Add из карточки/поиска/каталога, update/remove/reload. Невидимый товар явно помечается недоступным; checkout не молча теряет позиции. Изменённая цена/условия читаются сервером. По запросу — явная подпись. Количество целое 1..999999: техническая защита от переполнения хранения/сумм, явно показанная ошибка, без silent clamp 99. На validation/DB failure корзина остаётся. После commit убираются только отправленные позиции; позднее добавленные остаются. Persistent idempotency scoped к session owner/token, unique key в БД, повтор возвращает тот же номер даже после потери ответа. Не доверять browser prices. Комментарий/контакты сохраняются при ошибке. Онлайноплаты, автоматического резерва/списания нет.

## 8. Заказы
Проверить → в одной DB transaction создать native oc_order/oc_order_product, cp_order snapshot + idempotency, начальную историю и outbox → commit → подтвердить номер клиенту. Использовать нативную сущность заказа, без native paid flow или stock subtraction. Снимок содержит name/sku/product ID/qty/price nullable/currency/availability/условия/признак согласования на момент отправки. Товарные правки не меняют прошлое. Карточка: уникальный номер/UTC date/source/name/phone/email/comment, исходные позиции/цены/условия, текущий статус/ответственный/внутренние заметки/история/уведомления. Статусы Новый, В работе, Ожидает согласования, Согласован, Завершён, Отменён. Новая расценка менеджера отдельно от снимка с историей. Поиск/фильтры/реальные отчёты. Неподтверждённые запросы не выручка.

## 9. Обращения
Все текущие формы (обратный звонок, подбор, контакты, прочие блоки) → единый cp_lead registry: номер/type/contact/message/source/time/status/manager/history; фильтр/поиск по контактам, статус/заметки. Не создавать покупателей/подписчиков. В базовом выпуске не включать новую загрузку списков/файлов как пользовательскую функцию: условное требование ТЗ не активировано. Если когда-либо включается — отдельный quote, private files и ACL, без автоматической корзины; найденные/ненайденные/явное добавление. Импортные файлы администратора защищены отдельно.

## 10. Почта и аудит
Transaction outbox не теряется при сбое транспорта. В local только private capture, никаких MTA/SMTP. Worker leases/advisory lock, стабильный Message-ID, retry/backoff и ограничение попыток, состояние queued/processing/accepted/error и точная безопасная причина. Админ видит ошибку и может явно retry; дублирование клика не создаёт новые job для того же уведомления. Получатели/from/name общие настройки; secrets только private config. Accepted означает принято сервером/сохранено локально, не доставлено во Входящие. Ошибка почты не отменяет заявку и не просит клиента дублировать её. Аудит actor/time/entity/action для правок, публикаций, импорта и обработки. Без записи секретов/личного содержимого в обычные логи.

## 11. Управляемое содержимое
Настройки сразу форма вкладок: сайт/компания/requisites/logos/favicon/все телефоны/основной звонок/email/address/office/hours/messengers/socials/map; recipients/from/name; отдельная аналитика. Начальные значения только CatPart branding/current templates/local public config; нет выдуманных фактов. Существующие бизнес-тексты и условия страниц/главной/шапки/подвала/форм перенести в DB. Шаблон содержит структуру/правила/локализацию, не бизнес-контент. Главная: заголовки/тексты/изображения/advantages/buttons/products, enable/order каждого блока; ручная подборка или отмеченный automatic режим. Меню/подвал links/text/order/visibility, legal и заметки. Инфостраницы About/Delivery/Payment/Warranty/Contacts/Privacy — визуальное редактирование, SEO. Формы title/hint/button/consent/recipient. Контакты во всех шаблонах/формах/JSON-LD берутся из единой настройки. Изменения видны после сохранения без ручной правки PHP/SQL.

## 12. Карта, аналитика и подтверждения
Карта принимает штатный iframe либо HTTPS link Яндекс constructor/maps widget, извлекает src и проверяет точный allowlist hostname/path; не произвольный HTML/JS. Рендерится безопасным шаблоном iframe и preview; очистка убирает блок целиком без пустоты. Вкладка Аналитика и подтверждение прав: Metrika numeric ID, GA4 G- ID, Yandex/Google content values (без HTML), server validation. Один async loader/init на странице, только public production allowlist из CatPart, local не отправляет тестовые посещения, admin без аналитики, provider failure не мешает. Очистка отключает. Сохранять 114229167 и точные существующие options (ssr/webvisor/clickmap/ecommerce:dataLayer/referrer/url/accurateTrackBounce/trackLinks). Удалять старую инициализацию только после сравнения новой. Verification HTML files остаются прежними. Поле не равно подтверждение в кабинете.

## 13. SEO и маршруты
Все действующие /catalog/category, /tovar/slug, /poisk, /korzina, /stati/slug, info, sitemaps/robots/verification сохраняются. Slug conflict/reserved paths validation, обязательное confirm change, 301 со старого URL; последующие смены обновляют все прежние redirects прямо на актуальный, исключают cycles/длинные chains. SEO реально в HTML/canonical/OG/noindex/H1; sitemap только опубликованные доступные и индексируемые, structured data соответствует фактическим ценам без выдуманной выручки/остатка.

## 14. Права, файлы и доступ
Только native OpenCart login/session/CSRF user_token, три тестовые роли. Administrator site/users/maintenance/catalog/content/orders/leads; Editor content и catalog, без settings/users/orders/leads/maintenance; Manager orders/leads/reports, без правки catalog/content/settings/users. Каждая область имеет отдельные access/modify permissions, download/preview также. Direct URL/POST проверяется сервером; GET не меняет данные. Read-only role может смотреть, но не сохранять/удалять/восстанавливать/import apply/retry. Не выдавать всем admin ради ссылки. Приватные файлы вне docroot, MIME/content/size/extension whitelist; public изображения только безопасные image bytes/не SVG с JS. Тестовые аккаунты создаются заново; ни пароли, ни private config, ни CMTEH клиенты не копируются. Пароли не в отчёте/Git; инструмент создаёт автоматически в private ignored файле.

## 15. Проверки и выпуск
Настоящая локальная MariaDB + браузер native admin: phone everywhere; home block text/image/order/link; create product category/search; price/availability; article rich text/cover/SEO/sitemap; draft forbidden anonymous; one native order with correct snapshot; replay same order; broken mail preserves record/error visible; all forms; map set/clear; analytics/meta once/none local; editor/manager direct GET/POST ACL; repeated migration/update preserves data/settings/new order. Meaningful integration tests concurrency/idempotency/HTML/map/import/ACL against isolated data, короткие critical E2E, no source-text pseudo checks or viewport matrices. Baseline existing catalog checks adapt to task port/config; outdated mail-first expectations replace with persistence evidence, not disable coverage. Clean clone/package must run with test dependencies; no fallback syntax-only PASS. Один независимый security/correctness review всего изменения, narrow fix verification; отдельные повторные whole-change reviews не требуются по owner policy. G2 independent brief/spec coverage и G4 blind acceptance отдельно от code review.

Установочный пакет: deterministic ZIP + SHA256 + manifest source revision/upstream version/reused modules/licenses, no config/private data/DB dumps/runtime/user uploads. Default install migration preview; explicit loopback task apply and no production auto install. Safe additive update/backups/restoration directions, native engine/config preservation. Guide for owner with exact sections/actions, connected-functions matrix and honestly remaining optional native features. Локальные результаты отдельно от NOT RUN на хостинге. Рабочая локальная реализация является целью этого запуска согласно последнему уточнению.

## Вне рамок и внешняя приёмка
Мультисклад, резервирование, customer accounts, acquiring/online payment, 1С, рассылки — отдельные модули. Новая публичная загрузка списков/файлов не включается: условие «если включается» не активировано. Публикация на хостинг, production DB migration, реальные письма и тест рабочей роли на хостинге отложены прямым уточнением владельца «Действующие сайты CatPart и СМ ТЕХНО не изменяй». Они остаются NOT RUN в отчёте, не выдаются за локальный PASS. Никаких платных сервисов.

## Уточнения после независимой сверки
До переноса составить реестр зависимости → выбранные файлы/модули → установленная версия → результат совместимости из D:/codex/cmteh/opencart/extension/cmteh. Не устанавливать код без проверки его транзитивных зависимостей; проверенный полный модуль допустим, если не включает чужие настройки/витрину/складской процесс. В установочном манифесте перечислить реально установленные расширения. Правки upstream минимизируются (нулевые при выбранном extension подходе).
Основное изображение товара выбирается явно в галерее, сохраняет image_url/is_primary, подпись и alt; витрина читает тот же выбор. Импорт задаёт и показывает лимит времени/размера/строк, работает чанками с продолжением без дублирования и конкретной ошибкой вместо обрезки. Тест существующей корзины до/после migration удостоверяет те же product ID/qty и checkout правильных позиций.
Для каждой формы последовательность такая же, как для корзины: validation → transaction сохранения lead+outbox → commit → клиентское подтверждение номера; при transport failure сохранение не отменяется.
Повседневное меню не содержит неподключённых native функций и дублирующих ссылок/кнопок без понятной необходимости; серверные запреты действуют независимо от меню. Native admin shell получает логотип/название CatPart и жёлто-графитовые акценты, сохраняя рабочие native control conventions.
Перехват локальных писем реализуется private capture адаптером; запрет реальной внешней отправки — выбранная безопасная конфигурация изолированного стенда. Локальные тестовые сотрудники/пароли создаются инструментом в ignored private файле; от владельца не требуется готовить секреты. Один code review и две проверки полноты соответствуют запрошенному autopilot и owner policy, это проверка работы, а не новая функция продукта.
